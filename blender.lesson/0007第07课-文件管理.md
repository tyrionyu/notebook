## 一、今日学习知识点

### 1. 为什么"存文件"要单独学一课

前面 6 课你已经会看界面、会转视角、会移动物体、会进编辑模式选东西了。但有一件事一直没提：

> **你到现在做的所有东西，只要关掉 Blender，就全没了。**

新手最大的悲剧不是"建不出模型"，而是——

- 辛辛苦苦摆了 3 小时的模型，**手一滑关掉软件，没保存**；
- 或者保存了，但**第二天打开发现贴图全丢了**（一堆粉红色的方块）；
- 或者模型越改越烂想回到昨天那版，**发现没有昨天的文件**。

**保存不是"顺便按一下 Ctrl+S"，而是一整套"我的劳动成果怎么存得住、带得走、能回退"的体系。** 今天这一课就是把它一次性讲清。学会之后，你才真正有权说"这是我的作品"。

---

### 2. 核心动作一：保存 `Ctrl+S` 与另存为 `Ctrl+Shift+S`

| 操作                     | 快捷键                | 说明                                  |
| ---------------------- | ------------------ | ----------------------------------- |
| **保存（Save）**           | `Ctrl + S`         | 存到当前文件路径。**已有路径时直接覆盖，不弹窗**          |
| **另存为（Save As）**       | `Ctrl + Shift + S` | 弹出窗口，选新路径 / 新文件名。**保存为一份新文件，原文件不动** |
| **保存副本（Save As Copy）** | `Ctrl + Alt + S`   | 另存一份新文件，但**当前打开的还是原来那个**（继续改原文件）    |

> **三者区别一句话记：**  
> `Ctrl+S` = 覆盖原文件；  
> `Ctrl+Shift+S` = 换个名字/位置存，之后继续改**新文件**；  
> `Ctrl+Alt+S` = 备份一份出去，之后继续改**原文件**。

**"另存为"最重要的用法：存版本快照。**  
模型改到关键节点（比如"杯身结构定稿"），按一次 `Ctrl+Shift+S`，起名 `杯子_v2_定稿.blend`，再继续往下改。这样后面改砸了，随时能回到这个定稿版本。**这是新手最该养成的习惯——不要在一个文件里改到天荒地老。**

> **小技巧：`F2` 快速重命名。**  
> 选中场景里的物体按 `F2` 是**改物体名**；而在顶部菜单 `File` 区域，`F2` 也可以直接给**当前 .blend 文件**改名。改名是整理文件的第一步（见本课第 8 节）。

---

### 3. 核心动作二：`.blend` 文件长什么样

Blender 的工程文件后缀就是 **`.blend`**。双击它就能打开（前提是装了 Blender）。

一个 `.blend` 里装了什么？

- 你的所有物体、网格、修改器；
- 场景里的灯光、相机；
- 材质节点、**打包进来的贴图**（打包了才有，见第 5 节）；
- 界面的布局、你上次的视图角度。

> **它不是"图片"也不是"模型格式"，而是整个工程的"存档"。** 就像 PS 的 `.psd`、剪辑的工程文件。**记住这句话：给别人传 Blender 工程，传的是 `.blend`；给别人传"能到处打开的模型"，传的是 FBX / glTF（本课末尾一句话带过）。**

### 4. 核心动作三：自动保存与崩溃恢复（救命的一环）

Blender 会**定期自动保存**，防止你崩溃时丢掉全部工作。

| 机制                  | 说明                                                           |
| ------------------- | ------------------------------------------------------------ |
| **自动保存（Auto Save）** | 默认每隔约 **2 分钟**把当前工程悄悄存一份到临时目录                                |
| **退出时的临时文件**        | 崩溃 / 强退时，Blender 会把最近状态留在临时文件夹里                              |
| **恢复入口**            | `File → Recover → Auto Save`（恢复自动保存）/ `Last Session`（恢复上次会话） |

**关键认知：自动保存 ≠ 你的正式文件。**

- 它存在**系统临时目录**里，不跟着你的 `.blend` 走；
- 它是"救命稻草"，**不是"工作习惯"**；
- 临时目录可能被系统清理，**别指望它**。

> **真正的安全习惯是"改几步就 `Ctrl+S`"。** 建模时手指可以养成"动几下按一下 Ctrl+S"的反射——这个反射值千金。

**设置在哪：** `Edit → Preferences → Save & Load`

- `Auto Save Temporary Files`（默认开）；
- `Timer` 自动保存间隔（秒），可改成 60～120 秒更保险；
- `Save Versions`（保存版本数，默认 1，见下一节）。

---

### 5. 核心动作四：`.blend1` 备份文件是什么

在保存目录里，你可能会看到一个同名但后缀是 **`.blend1`** 的文件。它不是垃圾。

| 文件          | 是什么                              |
| ----------- | -------------------------------- |
| `杯子.blend`  | 你**当前**的工程                       |
| `杯子.blend1` | **上一次保存前的版本**（Blender 自动留的"后悔药"） |

每次 `Ctrl+S` 覆盖时，Blender 会把**旧的**那份改名成 `.blend1` 顶替掉更旧的。所以：

> **手滑保存了错误内容？把 `.blend1` 改名回 `.blend` 打开，你就回到了上一次保存前的状态。**

**设置在哪：** `Edit → Preferences → Save & Load → Save Versions`（默认 1，可调到 2～3，保留更多历史版本）。

> **注意：** `.blend1` 是"上一版"，不是"无限历史"。真要靠版本管理，还是用第 2 节的 `Ctrl+Shift+S` 手动存版本快照最靠谱。

### 6. 核心动作五：打包外部资源（Pack Resources）——解决"贴图全丢"

**这是新手最容易踩、也最值得单独讲的一个坑。**

#### 6.1 问题是怎么发生的

当你导入一张外部图片当贴图（比如第 27 课以后的 UV 贴图），Blender **默认只记录这张图片的"位置路径"，而不把图片本身装进 `.blend`**。

于是：

- 你在自己电脑上一切正常；
- 把 `.blend` 发给同事 / 拷到另一台电脑 / 图片被移动或删除 → **打开后所有贴图变成粉红色（找不到图）**。

#### 6.2 两种解决方案

| 方案           | 操作                                                    | 适用                                               |
| ------------ | ----------------------------------------------------- | ------------------------------------------------ |
| **打包（Pack）** | `File → External Data → Pack Resources`               | **推荐**。把所有外部图片/资源**复制进 `.blend` 内部**，文件变大但"自给自足" |
| **自动打包**     | `File → External Data → Automatically Pack Resources` | 勾上后，之后导入的资源自动打包，一劳永逸                             |
| 解包（Unpack）   | `File → External Data → Unpack Resources`             | 反过来，把打包的图片还原到磁盘文件夹                               |

> **备份铁律：** 任何"要发给别人 / 要归档"的 `.blend`，**存盘前先点一次 `Pack Resources`**。这一步能避免 90% 的"对方打不开/丢图"事故。

#### 6.3 相对路径 vs 绝对路径

`File → External Data → Make Paths Relative`（相对路径 / Relative Paths）/ `Make Paths Absolute`（绝对路径）。

- **相对路径**：图片位置是"相对于 `.blend` 文件"记的。**整个工程文件夹一起移动，链接不会断**。推荐的做法是把贴图和 `.blend` 放在**同一个文件夹（或同级子文件夹）**&#x91CC;，然后用相对路径。
- **绝对路径**：图片位置是从盘符开始记的（如 `D:\贴图\木头.jpg`）。**换电脑必断。**

> **原则：本地工程用"相对路径 + 打包"双保险；发给别人一定要打包。**

### 7. 打开与新建：别把工程搞混

| 操作         | 快捷键                             | 说明            |
| ---------- | ------------------------------- | ------------- |
| **打开文件**   | `Ctrl + O`                      | 打开一个 `.blend` |
| **新建**     | `Ctrl + N`                      | 新建空白工程        |
| **最近文件**   | `File → Open Recent`（顶部也可）      | 快速回到最近打开的工程   |
| **恢复上次会话** | `File → Recover → Last Session` | 崩溃后从"上次会话"救回  |

> **坑：`Ctrl+N` 新建会清空当前工程。** 如果当前工程没保存，Blender 会问你要不要存——**别手快按"不保存"**。新建/关闭前，先 `Ctrl+S` 或 `Ctrl+Shift+S` 存个版本，是最省心的习惯。

---

### 8. 顺手学一招：把文件整理明白

**保存文件时，命名清晰 = 未来的自己感谢现在的自己。** 建议：

```
项目文件夹/
├── 杯子_v1_素模.blend
├── 杯子_v2_定稿.blend
├── 杯子_最终.blend
└── textures/            ← 贴图统一放这里，用相对路径
    ├── 木头.jpg
    └── 金属.png
```

- **文件名带上"版本 + 状态"**：`_v1_素模` / `_v2_定稿` / `_最终`，一眼知道哪份能改、哪份别动；
- **贴图单独放 `textures/` 子文件夹**，`.blend` 放上一层，配相对路径，整包移动不断链；
- **导出给别人的格式一句话带过：**
  - **FBX / OBJ**：传统通用交换格式（游戏、其他三维软件），只带模型+基础材质；
  - **glTF / .glb**：现代网页/实时预览首选，能带材质贴图（`.glb` 是打包成单文件）；
  - 这些是 `File → Export` 出去的**成果格式**，和 `.blend`（工程存档）是两回事，第 30 课之后会具体用。

## 三、实操练习任务

> 今天不造模型，只练"存得住、带得走"。全程用默认立方体和一张随手找的图片即可。

**1. 第一次正式保存**

- 打开 Blender（默认立方体）→ `File → Save As`（或 `Ctrl+Shift+S`）；
- 建一个专门文件夹，例如 `G:\练习\Blender练习\`；
- 文件命名 `练习01_立方体.blend`，保存；
- 观察：标题栏出现文件名。之后改动后按 `Ctrl+S`，**不会再弹窗**（直接覆盖）。

**2. 存一个"版本快照"**

- 选中立方体，`G` 移动一下，再 `S` 放大一点；
- 按 `Ctrl+Shift+S` → 起名 `练习02_立方体_改过.blend` → 保存；
- 看文件夹：**现在有两个文件了**，`练习01` 原封不动，`练习02` 是改后的。**体会"版本快照"的意义。**

**3. 试验 Save As Copy（`Ctrl+Alt+S`）**

- 再按 `Ctrl+Alt+S` → 保存成 `练习03_副本.blend`；
- 保存后看一眼标题栏：**当前打开的仍然是 `练习02`**（不是副本）。理解它和"另存为"的区别。

**4. 认识 `.blend1`**

- 现在**再次**在 `练习02` 上做点改动（比如把立方体缩回去），然后 `Ctrl+S`；
- 打开文件夹看：除了 `练习02.blend`，**多了一个 `练习02.blend1`**；
- 把 `练习02.blend1` **复制**一份、重命名为 `练习02_v旧.blend` → 用 Blender 打开 → **你看到了"上一次保存前"的样子**。这就是后悔药。

**5. 制造"贴图丢失"现场，再用打包救回来**

- 从网上下/随手截一张图，存到桌面 `测试贴图.png`；
- Blender 里：新建一个平面（`Shift+A → Mesh → Plane`），拉到材质面板，把这张图接进材质的 **Base Color**（这一步照做即可，不用懂原理，第 21 课会讲）；
- 现在**把 `测试贴图.png` 从桌面删掉或改个名**（改名前先复制一份留底）；
- 回到 Blender，视图里物体变**粉红色/紫色**——你的贴图"丢了"；
- 复原图片名 → 贴图回来。

**6. 用 `Pack Resources` 永久解决**

- 把那张贴图放进**和 `.blend` 同一个文件夹**（或同级 `textures\` 子文件夹）；
- 重新把贴图接进材质 → `File → External Data → Pack Resources`；
- 保存 → 现在**删掉/移走外部图片**，再重开这个 `.blend`：**贴图还在！** （因为已经打包进文件内部了）；
- 体会：**打包 = 把资源搬进文件里，从此自给自足。**

**7. 设路径为相对**

- `File → External Data → Make Paths Relative`；
- 把**整个文件夹**（`.blend` + `textures\`）一起复制到 U 盘或另一个盘 → 打开 `.blend` → 贴图依然正常。**这就是"相对路径"的威力。**

**8. 体验自动保存恢复**

- 随便改点东西（先别 `Ctrl+S`）→ 用任务管理器**强行结束** Blender 进程（模拟崩溃）；
- 重新打开 Blender → `File → Recover → Auto Save` → 在弹出的自动保存列表里找最近的条目 → 打开看是不是你崩溃前的内容；
- 结论：**自动保存能救命，但不跟着你的文件走，别依赖它——该 `Ctrl+S` 还是要 `Ctrl+S`。**

**9. 整理一个"规范的项目文件夹"**

- 按第 8 节的结构，建一个文件夹：`.blend` 放根目录、贴图放 `textures\`；
- 把前面的练习文件按 `名字_vX_状态.blend` 命名规整一遍。

**10. 挑战：完整走一遍"交付流程"**

- 做一个简单改动（比如给立方体加一个材质颜色）；
- 依次执行：`Ctrl+Shift+S` 存为新版本 → `Pack Resources` 打包 → `Make Paths Relative` → 保存；
- 把这个 `.blend` 复制到另一个文件夹（模拟发给同事）→ 打开 → **确认一切正常、贴图不丢**。
- 恭喜，你已经掌握了"作品存得住、带得走"的完整闭环。

## 六、小提示与常见坑

- **坑 1：一直没保存，标题栏没有文件名。** 标题栏显示 `*.blend` 或带星号 = **有未保存改动**。看到星号就 `Ctrl+S`。
- **坑 2：`Ctrl+S` 之后找不到文件存哪了。** 第一次存一定用 `Ctrl+Shift+S` **自己选路径**；之后 `Ctrl+S` 才会静默覆盖到那里。别指望它帮你分类。
- **坑 3：关软件时弹窗问"是否保存"，随手点了"不保存"。** 这一下可能毁掉几小时。**养成关之前先手动 `Ctrl+S` 的习惯**，就不会被这个弹窗逼着临时决策。
- **坑 4：给别人发的 `.blend`，对方打开贴图全粉。** 你**没打包**，而且用的是绝对路径。发之前先 `Pack Resources`。
- **坑 5：`.blend1` 当成垃圾删了。** 它是你的"上一次保存前"。**删之前想想要不要留。**
- **坑 6：指望自动保存兜底。** 自动保存存在临时目录、会被系统清理、也不跟着 `.blend` 走。它是**安全网**，不是**安全带**。
- **坑 7：把 `.blend` 当 `.obj`/`.fbx` 发给别人。** `.blend` 是工程文件，别人**没装 Blender 就打不开**。要交换模型请 `File → Export` 成 FBX / glTF。
- **坑 8：一个文件改到天荒地老，没有历史版本。** 关键节点一定 `Ctrl+Shift+S` 存版本快照。**"能回退"是专业和业余的分水岭。**
- **心态提示**：本课没有漂亮的三维成果，全是"文件夹里的一堆文件"，但它是**阶段 1 的收尾，也是从"随便玩玩"走向"作品能保存、能交付"的分界线**。下一课起你会进入**阶段 2 · 基础建模**，开始真正"造东西"——那时你会庆幸今天把文件这套地基打好了。
